# PKM Nexus 0.4.0

轻量的 Chrome 个人知识收件箱。原生 JavaScript，无运行时第三方依赖、自建服务器、遥测、自动 AI 调用或后台同步。

## 安装

1. 使用 Chrome 120 或更高版本，打开 `chrome://extensions`。
2. 开启右上角“开发者模式”，选择“加载已解压的扩展程序”。
3. 选择本项目的 `extension` 文件夹，或构建后的 `dist/pkm-nexus` 文件夹。
4. 将企鹅图标固定到工具栏；点击图标打开侧边栏。“整理页”进入完整管理界面。

从旧版升级：保持原来加载的文件夹路径，在扩展管理页点击“重新加载”；关闭旧的整理窗口后重新打开。不要先卸载，以免丢失浏览器数据库。本次调整为页面截图和网站图标权限，Chrome 如要求重新启用扩展，请允许所需访问。原有记录保留，旧版“仅本地”记录改为参与下一次手动同步。所有同步电脑请使用同一新版本。

每台电脑安装同一版本，连接同一私有仓库和分支，即可手动同步。插件未发布到 Chrome 商店，暂不支持自动更新或手机浏览器。

## GitHub 配置

1. 在自己的 GitHub 账户中创建一个专用 **Private** 仓库。空仓库也支持，首次同步会建立默认分支。
2. 创建 Fine-grained personal access token，只选择该仓库，授予 **Contents: Read and write**；Metadata 采用 GitHub 的必要默认权限。不需要 Workflows、Actions 或账户管理权限。
3. 在整理页“设置与数据管理”填写用户名、仓库名和 Token。分支留空使用默认分支；非空时须是已有分支（空仓库允许首次建立分支）。
4. 点击“测试连接”，然后保存配置。点击“手动同步”才会拉取、核对、合并并上传记录。

Token 默认只保留当前浏览器会话；可选择在本机记住。浏览器存储不提供本项目额外的凭证加密，Token 只允许扩展受信任上下文访问，不会注入网页、写入仓库或导出备份。使用短有效期并只授权专用仓库。

本机数据首次同步后绑定仓库和分支，防止误混合两套数据库。需要换仓库时先导出备份，在独立浏览器配置中安装扩展并导入。本工具不自动创建 GitHub 仓库，也不支持公共仓库。

## 使用

- 选中文字后右键收集，或按 **Alt + Shift + S**。没有选中文字时带入网页标题和 URL。捕获先进入编辑草稿，点击保存后才进入收件箱。受限页面可手动粘贴。
- “捕获当前网页”支持导航后的普通网页；只在点击时读取标题、URL 与选中文字，填入编辑器，不直接保存。Chrome 内部页面等受限页面无法读取。
- **Alt + Shift + K** 打开整理页。快捷键冲突可在 `chrome://extensions/shortcuts` 修改。
- 记录自动进入“未分类”收件箱。草稿和记录保存在本机，收集不上传。
- 点击已有记录直接编辑，侧栏按钮变成“保存修改”，保留原 ID 与创建时间。四种收集入口用 tab button 直接选择。
- 在正文中 **Ctrl + V 粘贴图片**，或点击“添加图片”。附件原始文件独立存储，并自动插入 Markdown 相对路径；“预览”显示图片与音频播放器。
- “开始录音”时才请求麦克风；首次打开可见的授权页，点击允许后返回并开始录音，已授权时直接开始。拒绝、取消或关闭授权页会显示原因；“麦克风设置”可重新授权。点击“停止录音”后生成音频附件，再保存当前记录。已移除音频文件添加入口。每秒保存录音片段到本机，中断的录音可在整理页设置中恢复。单附件最多 20 MiB；录音接近上限时自动停止。
- 重复或相关内容进入“待处理收集”：查看已有记录、追加、另存或取消。相同网页的不同摘录不会被静默丢弃。
- “重复与相关”视图也会显示不同电脑分别收集的相同来源或正文；可选择两条合并，来源记录仍保留到回收站。
- **网页快照**：点击“捕获网页快照”保存当前可见页面的 PNG 图片，编辑器可预览、下载，确认后保存记录。它不是完整网页文件或自动滚动长图，单图片最多 20 MiB。旧版 MHTML 文件继续兼容。
- **清单**：只有一份，固定入口反复访问。无名称，选择 Todo / Idea 视图后添加 checkbox / bullet 或纯分割线，不填写分区名称，卡片上可直接完成待办。旧独立待办汇入这份清单，原文字保留为普通记录。
- **网页组**：多个链接组成一组，逐个标记已读，列表只显示网站图标与标题。拖入外部链接时读取目标网页标题，失败时采用链接文字或站点名。支持手动链接、多选当前窗口网页、拖入插件“已打开网页”的可拖动行。保存成功后关闭所选标签页；拖入已有组卡片时立即追加并在写入成功后关闭。可以取消“保存后关闭”。固定标签页与发生导航的网页保留。当前不能接管浏览器原生标签栏拖动，拖出会变成新窗口；请使用插件“选择已打开网页”多选归组或拖入该列表的行。
- 搜索涵盖标题、正文、清单项目、网址组、标签和来源；类型与标签可筛选。用途字段已移除，旧用途在编辑升级时转为正文备注。批量添加标签、标记已整理、移入回收站。
- 项目关键词按任意关键词包含匹配。先查看匹配结果，再预览并添加关联；不会自动分类，不需要 AI。
- 每次同步由用户点击触发，读取远程固定提交后按共同版本比较。冲突保留双方，用户选择本地、远程或手动合并 JSON，之后再次同步。
- 同步期间的新编辑继续待同步；请求失败保留本地数据。更新远程分支不执行强制推送。
- 回收站可还原。移除当前正文后保留最小删除标记，防止旧设备无提示复活；**不代表清除了 Git 历史、其他设备或已有备份**。
- 所有已保存记录都参与下一次手动同步，不再提供“仅本地、不上传”开关。
- **保存到本地**下载完整 ZIP：仓库结构的 JSON、索引、删除标记、图片、录音、PNG 页面截图（兼容旧 MHTML），以及 Markdown、草稿、待处理收集。附件没缓存时，这次主动备份会下载所需文件；文件缺失或校验失败则停止，避免生成不完整的成功备份。不会上传任何数据。
- 在设置中“导入 JSON / ZIP”可离线恢复完整 ZIP。导入先预览，同 ID 差异默认跳过，用户可明确选择更新。JSON 单独导出只含数据和附件清单；Markdown 单独导出提供文字与附件路径，均不包含二进制媒体。完整媒体备份请选择 ZIP。
- 未保存草稿也进入 JSON 备份。旧版本编辑草稿可在设置中恢复为新记录，不覆盖其他窗口刚修改的正文。

卸载扩展或删除浏览器配置前务必保存完整本地 ZIP；浏览器内部副本不能替代备份。仓库当前文件也不能代替其他离线设备尚未上传的内容。备份包当前支持最多 512 MiB、60,000 个文件；大型媒体库后置。

## 数据布局

```text
data/YYYY/MM/<id>.json       # 正文与元数据，正文为 Markdown
tombstones/<id>.json         # 移除当前正文后的最小删除标记
assets/<sha256>.<ext>        # 图片、录音、PNG 页面截图（兼容旧 MHTML）二进制文件，按内容复用
index/global_index.json     # 可重建的轻量索引，SHA-256 内容版本
```

字段说明见 [DATA-SCHEMA.md](DATA-SCHEMA.md)。四种收集类型共享 v4 Record 格式，图片、音频可以同时附在一条笔记上。项目规则也是独立记录，与笔记使用相同版本核对机制。新增、编辑、删除都允许修改记录文件；每次上传将新附件、记录变化与索引一起提交，无需 GitHub Actions。其他电脑先拉取附件描述，点击加载时下载媒体，已缓存的媒体可离线使用。损坏的索引或手动改动的 JSON 可在设置中主动“扫描仓库并同步”修复；无效文件会停止处理，不会被悄悄丢弃。

IndexedDB 保存内容、元数据、全文搜索文本、持久化待处理收集、冲突版本和同步临时数据。列表分页只读取元数据；同步快照不读取未改变的正文，拉取的正文先逐条暂存在磁盘，完成后以事务应用。完整备份和主动扫描会处理全部内容，体积取决于记录数量。

## 开发与验证

```powershell
npm.cmd install
npm.cmd test
npx.cmd playwright install chromium
npm.cmd run test:browser
npm.cmd run test:media-browser
npm.cmd run test:types-browser
npm.cmd run build
```

测试依赖仅用于开发，不进入发布包。核心测试使用独立 IndexedDB 数据库和模拟 GitHub Git API；浏览器测试在真实 Chromium 扩展环境验证界面与双设备同步。测试不访问真实账户、创建真实仓库或使用真实 Token。

构建无需转译或打包器，只将运行文件复制到 `dist/pkm-nexus`。加载源码 `extension` 目录也可直接使用。

## 第一版边界

支持文本、链接、图片和音频。支持当前可见页面 PNG 截图；不支持无限滚动内容自动加载、实时多人协同、字符级合并、移动端或自动 AI 整理。关键词是简单包含匹配，不做中文语义理解。首次同步、全量扫描和大备份需要保持操作窗口打开；关闭时本机修改仍保留，下一次手动同步会重新核对远程状态。网页读取权限用于用户触发的捕获，没有常驻网页内容脚本或后台扫描。

当前数据结构与交互规则见 `DATA-SCHEMA.md`，验证证据见 `VALIDATION.md`；早期 v0.2 设计中与新类型不一致的部分已经由 v4 数据格式取代。
