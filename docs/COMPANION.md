# PKM Nexus Windows 配套程序 0.4.1

0.4.1 使用原厂签名运行时、可读源码及原生托盘界面，完整插件内置可下载的便携 ZIP。旧 0.4.0 继续停用。当前程序 EXE 的签名状态及扫描记录随 RELEASE.json 提供。参见 [安全记录](SECURITY-2026-10-17.md)。

此版本配合扩展 0.7.3，支持 v5 项目层级、关系图、喜爱及网页划线删除。保留现有资料库；更换程序目录后需主动重新连接扩展。同步采用本地资料库与个人 Drive 的唯一入口。

目标环境：Windows 10/11 x64。同步助手使用系统自带 .NET Framework 的原生小窗口和托盘，后台服务自带 Node 24 运行时；用户不需要另装 Node、数据库或 Google Drive 桌面客户端。

## 安装与连接

1. 在 `chrome://extensions` 加载完整插件 0.7.3 的 `pkm-nexus` 文件夹。已有用户更新时保持原加载目录并重新加载，不要先卸载。
2. 在扩展设置中点击“下载 Windows 本地应用”。先退出旧版，将 ZIP 解压到固定目录，双击 **PKM-Nexus.exe**，保留同目录 **runtime** 和 **app** 文件夹。无需脚本安装器或管理员权限，不会自动创建快捷方式或开机启动项。
3. 程序显示同步助手小窗口。点击“设置与资料管理”打开完整管理页，在“连接浏览器扩展”中填写扩展设置页的扩展 ID 并点击“连接此扩展”。以后双击 PKM-Nexus.exe 再次打开；管理服务只监听 `127.0.0.1`。
4. 在扩展“设置与数据管理”点击“连接并启用本地资料库”。已有记录和缓存附件会交接到本地；以后保存会自动交接。停止连接不会删除浏览器数据。
5. 两台电脑各自完成上述步骤。不要直接同步 SQLite 文件。

官方 Node 保留 OpenJS 签名，自编译的应用 EXE 当前尚无发行签名。杀毒扫描通过与发布者签名是两项不同信息，不将未签名等同于恶意软件。Google 桌面应用客户端已内置，应用仍处 Testing，用户选择暂不添加测试账号；目前尚未向所有 Google 用户开放。本包没有 Google 或商店审核背书。

## 小窗口与右下角托盘

- 小窗口显示本地目录、待上传条数、已连接扩展数、当前 Google 账号与同步结果，提供登录、立即同步和设置入口。
- 最小化或点击 × 均隐藏到右下角托盘；双击图标或从菜单选择“打开小窗口”恢复。重复启动返回已有实例。
- 托盘菜单可立即同步、打开设置或退出助手。退出关闭助手及其管理服务；已启用的 Windows 定时任务独立运行，需在设置中关闭自动同步才能移除。退出不删除资料。
- `PKM-Nexus.exe` 是 GUI，`PKM-Nexus-NativeHost.exe` 是固定入口通信桥，`PKM-Nexus-Platform.exe` 只提供受限 Windows 操作。`runtime/node.exe` 保留 OpenJS 原厂有效签名，`app/` 保存可读源码。不要单独运行辅助 EXE。

## 每位用户登录自己的 Google Drive

OAuth 客户端标识应用，用户授权标识数据属于谁。同一个应用客户端可供不同用户登录，访问令牌、刷新凭证和资料库分别属于实际登录的用户；资料不会汇总到开发者的 Drive。应用显示当前账号，并只允许绑定该账号自己拥有的资料库。切换账号后，原资料库的云端读写会停止，需登录原账号或使用独立资料库；不会自动迁移已有资料。

普通用户只需点击“登录自己的 Google 账号”并在系统浏览器授权；第二台电脑使用同一账号选择相同资料库。每位用户无需创建 Google Cloud 项目或导入配置 JSON。

当前 Google 应用开放状态：已创建独立 `pkm-nexus` 项目、启用 Drive API、创建桌面客户端并仅声明 `drive.file`。应用仍在 Testing 且未添加测试用户，不能将其描述为已允许任意账号登录。用户计划稍后在 GitHub 发布；公开主页、隐私页及部署步骤已准备在 [GITHUB-PAGES.md](GITHUB-PAGES.md)。发布网页并补齐 Google 品牌信息、完成适用核验和应用发布后，再执行真实账号及双设备验证。

## 开发者一次性配置 Google 登录

当前已在独立 Google Cloud 项目 `pkm-nexus` 创建“PKM Nexus Windows”桌面客户端，配置由构建统一带入应用。普通用户只需登录自己的账号。以下步骤供应用开发者后续维护或更换客户端：

1. 在 Google Cloud Console 创建或选择项目，启用 **Google Drive API**。
2. 配置 Google Auth Platform 的品牌、支持信息和受众。私人测试时选 External / Testing，把两台电脑使用的 Google 账号加入测试用户。
3. 在 Clients 创建 **Desktop app / 桌面应用**客户端，下载客户端 JSON。将文件放在 `companion/google-oauth.json`，或构建时通过 `PKM_NEXUS_GOOGLE_CLIENT_FILE` 指定本机 JSON 路径。
4. 运行 `npm run prepare:companion` 准备目录。构建只带入应用的桌面客户端 ID / 配置，拒绝用户访问令牌、刷新令牌、服务账号或私钥。客户端配置不会授权开发者账号的 Drive。扫描当前目录并保留报告后，运行 `npm run build:companion`、`npm run build` 打包；新加入 OAuth 配置后也需重新扫描。
5. 分发后，用户点击登录，在系统浏览器选择自己的 Google 账号并授权（PKCE、随机 state、一次性回环回调）。设置中的 JSON 导入仅保留在“开发者配置”折叠区域，供本机测试覆盖。
6. 测试模式请求 Drive 权限时 refresh token 通常 7 天失效。长期使用前将应用按 Google 要求配置为合适的正式发布状态，完成适用验证；发布状态调整不等于商店审核通过。

只请求 `drive.file`；通过 Drive 的当前用户接口显示账号，不增加身份权限。只绑定当前账号自己拥有的 PKM Nexus 文件夹。每次同步先确认账号；后续请求也校验令牌所属账号，防止后台进程继续使用换号前的凭证。刷新凭证用 Windows 当前用户 DPAPI 加密保存在应用配置目录，不能跨用户复制。

## 自动同步与离线

授权并选择远程资料库后，可以明确勾选“允许每小时自动同步，并在登录后补同步”。安装本身不会开启任务。该开关注册当前用户的 **PKM Nexus Hourly Sync** Windows 任务，关闭开关会移除任务。使用交互登录身份，不保存 Windows 登录密码。

关闭 Chrome 后仍能同步已经交接到本地的内容。尚留在浏览器而没有成功交接的数据要等扩展再次运行。电脑关机、睡眠、用户未登录和断网时无法承诺执行；任务设置为错过后补执行。可随时点击“立即同步”。Chrome 运行时每分钟通过 alarms 重试本机交接并接收本地增量，不要求收集页面保持打开；页面重新显示时也会接收本地修改。这一步只访问本地程序，不请求 Google。

每次先获取远程变化，再发布本地待同步修订。出现版本分叉时保留双方，在本地管理程序“待处理冲突”选择版本或合并正文；其他记录仍可同步。修改时间不作为覆盖依据。

## 数据与 LLM

默认资料库在 `%LOCALAPPDATA%/PKM Nexus/Knowledge`，可在关闭自动同步后切换为另一个目录：

```text
records/<前缀>/<id>.json   当前记录，允许显式导入外部修改
assets/<sha256>.<ext>     已下载的原始附件
readable/<id>.md          可重建 Markdown 阅读视图
.nexus/revisions/         不可变修订及父版本关系
.nexus/index.sqlite       本机可重建索引，不上传
.nexus/vault.json         本地资料库身份
```

LLM 可以读取 JSON 和 Markdown。Markdown 是派生视图，不反向同步；修改 JSON 后点击“导入外部 JSON 修改”，会校验 ID、结构和当前版本。存在冲突时先处理冲突。尚未导入的外部修改如果遇到同步更新，会先复制到 `.nexus/recovery/external`，管理界面显示恢复提示，避免静默覆盖。第一版外部导入处理已有记录，不扫描任意新文件。资料列表分页查询，不载入全部正文；本机全文搜索覆盖已经同步的文字。图片和录音只在打开时下载，缓存后可离线使用。

Drive 文件夹中的 `changes-*.json` 是不可变同步批次，附件以内容哈希命名。不要通过修改/删除批次文件来编辑笔记。用户可以从 Drive 下载资料；本地 records/readable 提供日常阅读和整理入口。第一版保留修订历史，尚未实现历史压缩和回收；超大资料库需要在后续基准测试后再承诺规模。

## 卸载与开发

先在管理页断开 Google 授权，或在 Google 账号的第三方连接中撤销；再点击“断开本机连接并关闭自动同步”，移除本程序的任务与主机注册。从托盘退出助手，删除解压的程序目录即可。资料库和用户配置保留，不自动删除用户知识文件。

开发命令：`npm run prepare:companion`（准备审查目录）、`npm run prepare:extension`（不含安装包的插件预览）、`npm run companion:serve`（输出一次性管理链接）、`npm run companion:sync`。运行源代码需要 Node 24；构建需要 Windows x64。不要把管理链接当作公共分享链接。

政策与隐私依据见项目中的 `docs/GOOGLE-COMPLIANCE.md`、`docs/ARCHITECTURE.md` 和 `PRIVACY.md`。真实账号联调、发行签名和公开审核尚待完成。
