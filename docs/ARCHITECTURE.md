# 本地资料库与 Google Drive 同步路线

更新：2026-10-17。唯一同步路线：Chrome MV3 扩展 + Windows 10/11 本地配套程序 + Google Drive API。兼容既有 v4 内容及 v5 项目树、项目内 ID 图、喜爱与网页划线删除。组织模型见 [分类与项目说明](ORGANIZATION.md)。

当前版本：扩展 0.7.3，Companion 0.4.1。旧 0.4.0 停用；新版本使用透明运行时，检查扫描与完整性后恢复内置下载，应用 EXE 的签名状态如实记录。浏览器收集整理与同步链路分别验收；模拟 Google HTTP 端点不能替代真实账号联调。

## 已确认的边界

- 单人使用，不做实时多人协作；不同设备基于旧版本编辑仍然构成冲突，不能按修改时间直接覆盖。
- 每台电脑安装本地配套程序，不需要 Google Drive 桌面客户端，也不运营应用服务器或托管数据库。远程文件保存在用户自己的 Google Drive。
- 完整插件包内置 Windows 安装 ZIP，设置页提供离线下载及安装步骤。构建先生成配套程序，再将安装 ZIP 与版本、大小、SHA-256 清单放入 extension/installers；不需要单独下载站点。扩展不执行安装器，用户下载、解压后主动安装。
- 扩展继续提供网页收集、编辑、IndexedDB 持久化和备份；本地程序不可用时，收集内容仍然保留。
- 内容使用独立 JSON 文件，正文为 Markdown，附件按 SHA-256 寻址；生成可重建的 Markdown 阅读视图。同步信息和凭证不混入内容格式。
- 本地 SQLite 是可重建索引，负责分页和搜索；不把运行中的数据库文件上传到 Drive。
- Google Drive 负责跨设备存储与传输，版本比较和冲突处理由本地程序执行。扩展没有其他云同步适配器或凭证输入。

## 交付顺序

1. 0.4.1 稳定性版本：历史待办渲染和迁移、录音恢复时长、数据库重试、待同步口径、ZIP 校验及构建证据，并补回归测试和自动检查。
2. 本地配套程序：Windows 可安装分发、Native Messaging、开放资料库、管理界面、分页搜索、附件分块传输。
3. Drive 适配器：OAuth 桌面流程、离线凭证、安全存储、增量同步、版本冲突、独立的每小时后台任务。
4. 真实 Google 账号验证。已创建独立 pkm-nexus 项目及桌面 OAuth 客户端；模拟验证不能替代真实授权及上架审核。

## 本地与远程职责

Windows 使用 WinForms 小窗口与 NotifyIcon 托盘；关闭 / 最小化隐藏到托盘，重复启动恢复已有实例。GUI 隐藏启动未经改写、保留 OpenJS 有效签名的 Node 运行时和可读源码，认证回环管理 API，退出释放服务；完整管理页取得独立的一次性会话。Native Messaging 桥只转发固定脚本的 stdio，Windows 辅助程序只允许 DPAPI、当前用户主机注册及受限任务等固定操作。没有脚本安装器和编码命令。便携目录由用户主动解压、连接，自动同步需另外开启。

Google OAuth 客户端属于应用，构建时统一配置；用户各自在系统浏览器登录自己的账号。凭证和当前账号身份保存在当前 Windows 用户的加密配置中。资料库绑定 Drive 用户标识及文件夹 ID，只允许自己拥有的文件夹；同步及远程附件读取先验证账号，后续请求校验预期账号，阻止换号后沿用旧资料库或缓存令牌。构建拒绝内置用户令牌和服务账号。独立 pkm-nexus 项目的桌面客户端已创建并内置，Google 应用仍处 Testing；用户选择暂不加入测试用户，公开使用需完成主页、隐私政策和 Google 应用发布。

扩展 IndexedDB 是浏览器内的持久化收集队列。本地程序接收内容并写入资料库后才确认交接，确认与浏览器待交接状态分开处理；编辑时比较基准版本，不能覆盖另一端的新修改。浏览器关闭后，已交接的本地资料仍可由 Windows 后台任务同步；尚未交接的浏览器内容须在扩展再次运行后传递。

资料库包含 records、assets、readable 和同步修订历史。每次修改保存父版本标识，修订不可变；同一记录存在多个互不继承的版本时保留冲突。解决冲突产生引用双方的新修订。回收站和最小删除标记继续传播，远端文件丢失不等同于用户删除记录。

Drive 使用普通可见的专用资料库文件夹。远端变化采用不可变批次发布，先上传已引用附件，再发布记录批次；失败重试复用已分配的文件 ID。客户端以持久化游标消费变化，完整应用后才推进游标。新增修订到达顺序不影响最终版本关系。不同记录的冲突不阻止其他记录同步。

## 部分加载

- 列表只查询分页元数据，正文打开时读取；文字索引在本机维护。
- 新设备获取记录及元数据，图片与录音按需下载和校验，可缓存离线。没有缓存的附件在离线时不能打开。
- 全文搜索只覆盖已下载并建立索引的正文，不宣称能离线检索尚未获取的资料。
- 不把整个资料库打成 ZIP 当作同步单元，也不每小时扫描和传输完整媒体库。
- 增量变更批次可后续增加快照和压缩；修订历史回收必须有设备进度和离线设备策略，第一版不自动删除历史。

## 调度与 LLM

用户明确启用后，Windows 任务每小时运行；登录后补执行，睡眠、关机和断网期间不承诺执行。任务由操作系统管理，不依赖 Chrome 的 Native Messaging 进程持续存活。界面提供立即同步、最近结果和关闭自动同步入口。

LLM 可读取 JSON、Markdown 视图和格式说明；修改通过版本检查写入。Markdown 是派生阅读视图，不能同时作为第二套权威数据。用户在 records 中的外部修改需要经过导入校验和版本检查。

## 验收场景

两台独立资料库离线编辑同一条记录、删除与编辑交错、响应丢失后的幂等重试、进程中断后的恢复、附件缺失与校验失败、超过 Native Messaging 单消息上限的记录和附件、分页不载入全库正文、关闭 Chrome 后运行同步命令、凭证不出现在记录/备份/日志、未授权时无 Google 网络请求。

规范依据与发布前工作见 [GOOGLE-COMPLIANCE.md](GOOGLE-COMPLIANCE.md)。

## 浏览器交接与状态

已启用本地连接时，保存后触发交接；Chrome alarms 每分钟重试本机交接并接收本地变化，不请求 Drive。即使收集和整理页面关闭仍可工作。浏览器关闭后尚未交接的数据不能同步。接收的记录、附件描述、版本链接、冲突集合与游标在同一 IndexedDB 事务提交；并发编辑导致事务失败时不推进游标。

云同步失败仍返回本地交接成功，保留 Drive 错误和待上传数；界面区分浏览器持久化、本地资料库持久化和本机上次 Drive 同步。冲突处理统一在本地管理界面。

新设备遇到项目依赖记录冲突时，只延后受影响的依赖组，其他记录继续交接；延后记录 ID 与游标一起提交，后续通过 records.get 重试。冲突解决后补齐项目关系图；非冲突导致的无效依赖仍中止事务并保留进度。
