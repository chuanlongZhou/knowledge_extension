# PKM Nexus 标准演示与验收流程

适用版本：0.5.2 起。固定用例和数据：`tests/fixtures/demo-cases.json`。所有用例使用 N / P / T / G / O / D / H 编号；每一步记录操作、预期、实际、截图和状态，不能只凭“按钮点击成功”判定通过。

## 1. 环境与准备

1. 使用独立 Chrome 演示配置或测试账号，不能清空日常资料库。升级保持原加载目录并重新加载，不先卸载。
2. Chrome 120+，Windows 10/11 x64。网页访问由用户按需授权；首次麦克风由用户明确允许。自动化正向场景预授网站权限并使用虚拟麦克风，不能替代首次权限弹窗或真人拾音验收。
3. 本轮新增记录统一以 `[演示编号]` 命名，标签为 `演示, 学习`。主题分组使用 `[工作]`、`[生活]`、`[学习]`、`[产品]` 前缀及无名称分割线，仍只有一份 Todo / Idea 清单。
4. 图片使用仓库自带 `extension/icons/penguin.png`；录音两秒以上。真人验证读出“这是 PKM Nexus 演示录音”，避免录入个人或工作敏感信息。
5. 网页样例为 Wiki、Bilibili 视频和用户指定的 CHETNA 站点。活网模式不得用离线 HTML 偷换结果；403 / 412、验证码、空白地图、登录要求均记录阻塞，不绕过安全屏障。
6. 先备份再做真实同步。真实 Google 演示使用专用测试文件夹，两端同一 OAuth 应用及账号；不记录令牌、邮箱、回调 URL 或登录截图。

## 2. 两种可重复执行方式

运行 `npm ci` 和 `npx playwright install chromium` 后：

```text
npm run test:demo              # 固定离线网页 + 虚拟麦克风 + 模拟 Drive，完整流程
npm run test:demo:live         # 三个真实站点的捕获与截图，不替换真实响应
npm run demo:manual            # 根据最新结果重新生成 Markdown 和内置帮助
npm run test:guide             # 断网加载帮助、图片、目录、来源下载及安全渲染
npm run demo:open              # 打开刚完成的独立演示资料库，方便手工复查
```

默认离线回归保证测试数据稳定；所有离线网页和模拟 Drive 截图都带测试标识。活网测试单独输出结果，即使固定回归通过也不自动把真实站点或真实 Google 标为通过。

## 3. 验收矩阵

| 编号    | 场景                          | 核对要点                               |
| ------- | ----------------------------- | -------------------------------------- |
| N01     | 捕获当前网页                  | 标题、来源、保存前草稿；未选字不抓全文 |
| N02     | 直接文字                      | 保存与重开后逐字一致                   |
| N03     | 文字加录音                    | 两秒以上，非空音频，实际可播放         |
| N04     | 网页、文字、图片、音频        | 同一 ID 同时保留四类数据               |
| P01—P03 | Wiki / Bilibili / CHETNA 快照 | 真实可见页面、可解码 PNG、URL、重开    |
| T01—T04 | 两组 Todo、两组 Idea          | 主题、分割线、完成状态、全局唯一 ID    |
| G01—G02 | 视频组、Wiki 组               | 链接数量、可读标题、已读状态、互不覆盖 |
| O01     | 批量标签与整理                | 只有所选记录改变                       |
| O02     | 项目关键词                    | 先预览再关联，不自动改正文             |
| O03     | 搜索与筛选                    | 正文命中、类型与标签组合               |
| O04     | ZIP 备份与恢复                | 两个独立浏览器，ID、内容、媒体哈希一致 |
| D01     | 浏览器到本地                  | 交接 ID 和媒体，不将测试桥当作正式安装 |
| D02     | 两设备同步                    | A 上传、B 拉取修改、A 再拉取           |
| D03     | 过期副本冲突                  | 双方保留，人工处理后收敛               |
| D04     | 部分加载                      | 只拉元数据，点击后下载并校验           |
| D05     | 断网及重试                    | 不丢待上传修改、不提前确认成功         |
| D06     | 真实 Google                   | 配置 OAuth 后在两台 Windows 人工验收   |
| D07     | 每小时任务                    | Chrome 关闭仍运行、日志与关闭任务      |
| H01     | 内置说明书                    | 断网可读、图片全、两个入口可达         |

完整的逐步操作与输入以固定用例文件为准；说明书会把本轮操作及截图逐项列出。

## 4. 判定与证据

- **通过**：操作后的 UI 和持久化数据均满足验收条件；媒体必须可解码或可播放，不能只看附件文件名。
- **失败**：应用行为不符合预期。记录错误、复现步骤、最后页面和截图，保留原始结果。
- **阻塞**：真实站点风控、未配置 OAuth、用户尚未授权或外部服务不可达。阻塞不是通过，也不能用模拟结果冒充。
- **未执行**：本轮不适用或依赖尚未满足。不得从历史通过记录继承本轮状态。
- 每次运行产生新的 `test-results/demo-runs/<时间>-<模式>/report.json`、浏览器配置及下载文件；发布用的最近结果保存在 `docs/demo-results`，截图保存在 `extension/guide/images`。
- 截图命名：`模式-用例编号-步骤号.png`。截图是实际浏览器渲染，不用合成 UI；测试标识说明测试替代项。

## 5. 人工活网检查

1. Wiki：显示文章标题与正文再截图，确认正文不是权限或错误页。
2. Bilibili：显示视频页再截图；不用登录、验证码破解或下载视频来规避限制。只验证当前可见画面，播放质量和完整视频不是扩展快照能力。
3. CHETNA：等待地图或图表真正加载；如图层请求失败，截下失败状态并标记阻塞。视口截图不等于保存可交互地图。
4. 录音：用真人声音复验 N03 / N04，试听内容；自动化虚拟麦克风只验证录制、存储、播放管线。
5. Google：用户自己完成 OAuth 授权。D06 / D07 完成前，版本报告保持“真实云同步待验收”。

## 6. 结束与复测

导出本轮完整 ZIP，保留报告、截图及媒体校验值。测试文件夹只由测试程序在工作区内管理，不删除日常浏览器数据，不更改已安装的 Native Messaging 注册，也不自动注册每小时任务。外部站点改变或用例数据更新时，保留旧结果并标记新的运行时间和版本。

## 7. 内置示例专项回归（0.5.4）

另有独立于原 25 项演示的九个浏览器场景，运行 `npm run test:examples-browser`：

| 场景 | 操作                         | 验收条件                                                       |
| ---- | ---------------------------- | -------------------------------------------------------------- |
| E01  | 空库打开收件箱               | 六条只读示例直接可见，个人记录与待同步记录仍为空               |
| E02  | 离线打开全部示例             | 图片与快照解码，测试录音实际播放；预览不写入数据库             |
| E03  | 保存多媒体示例               | 同一条普通记录保留来源、文字、图片和录音，按现有规则待同步     |
| E04  | 编辑后再次保存同一示例       | 不重复、不覆盖用户修改；核心测试另验证回收站与删除标记不被复活 |
| E05  | 隐藏、刷新、设置恢复         | 隐藏选择保留；恢复预览不影响个人记录                           |
| E06  | 已有记录时打开 360px 侧栏    | 底部可见版本号和“查看 6 条内置示例”；点击即到示例区，默认展开  |
| E07  | 隐藏后刷新、点击侧栏底部入口 | 恢复所有示例，个人数据库无新增记录                             |
| E08  | 全部加入，再次全部加入       | 六条普通记录、四个去重附件；第二次新增为零，已有编辑不被覆盖   |
| E09  | 360px 侧栏及网络核对         | 无横向溢出；预览、单条保存、整批导入均不请求外部网站           |

`npm run test:examples` 验证示例来源、附件校验、并发导入、用户编辑/删除保护及共享附件元数据。`npm run examples:bundle` 仅供开发者在已有对应测试资料库时重建静态示例包；普通构建直接使用随仓库提供的示例，无需重跑测试或联网。短录音未选入示例，使用已验证多媒体记录中的较长测试录音；以后录音验收同时检查持久化时长达到两秒。

## 8. 网页标题与 CORS 回归（0.5.4）

运行 `npm run test:websites-browser`，使用未经修改的正式 manifest 和独立浏览器资料夹。Bilibili 请求由测试拦截，不访问实站；正向跨域读取使用本机 HTTP 测试服务器，故意不返回 `Access-Control-Allow-Origin`。仅在测试资料夹中预先批准单站权限，再通过真实点击调用 `chrome.permissions.request`；不声称自动化点击了 Chrome 原生授权确认框。

| 场景 | 操作                                               | 验收条件                                                                     |
| ---- | -------------------------------------------------- | ---------------------------------------------------------------------------- |
| W01  | 无授权调用 Bilibili 标题读取，分别传入不同拖拽标题 | 无网页请求、无 CORS 错误；无标题时显示域名，有标题时保留本次文字             |
| W02  | 侧栏手动加入及拖入 Bilibili 链接，保存网页组       | 原始 URL 和拖拽标题保留，无额外网站授权                                      |
| W03  | 本机测试站点授权前后读取标题                       | 授权前零请求；单站授权后读取真实标题，不要求服务器提供 CORS 头；已有标题优先 |
| W04  | 403 后重试、撤销权限后再读缓存 URL                 | 失败可重试；撤销后无新增请求，不使用已缓存标题绕过权限检查                   |
| W05  | 已授权站点跳转到另一个未授权域名                   | 不跟随跳转，链接可保存，无 CORS 错误                                         |

截图与报告：`test-results/websites-without-permission.png`、`test-results/websites-browser-report.json`。包内复验：构建后运行 `node tests/websites-browser.mjs --built` 与 `node tests/examples-browser.mjs --built`。这组用例不替代真实 Bilibili 页面快照验收。
