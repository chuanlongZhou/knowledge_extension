# 2026-10-17：Companion 安全告警与停发记录

状态：**旧 0.4.0 继续停用，告警分类尚无厂商结论。用户明确要求完成修复并恢复新版下载：0.4.1 通过透明运行时、实际扫描、原厂运行时签名及文件完整性检查后交付。应用自编译 EXE 尚未签名，如实记录；不以未签名为由永久关闭新版下载。**

## 首次告警（0.4.0）的事实

- 用户的 WithSecure Client Security Premium 事件截图显示：2026-10-17 18:39（截图中的本机时间），`dist/PKM-Nexus-Companion-0.4.0/PKM-Nexus-Engine.exe` 被判为 `Trojan.TR/W64.Malware`，处置为 Harmful file renamed。
- 该程序是本项目生成的本地同步后台，源码入口 companion/main.mjs；负责本地资料库、Chrome Native Messaging、回环管理 API 和用户授权后的 Google Drive 同步。托盘窗口及图形安装器是单独的 C# WinForms 程序。
- 当前构建使用 esbuild 打包应用代码，Node SEA 生成资源，再通过 postject 写入 Node 可执行文件。脚本清除原 Node Authenticode 签名后，没有添加发行签名。
- 只读验证显示，`C:/Program Files/nodejs/node.exe` 签名 Valid，发布者 OpenJS Foundation；当前生成的后台、GUI 和安装器均为 NotSigned。签名状态本身不能证明恶意或无害。
- 程序源码中存在隐藏启动子进程、PowerShell EncodedCommand、注册 Chrome 本机消息主机，以及由用户开启 Windows 定时任务的行为。这些行为有产品用途，也需要独立的安全审查；不能据此判定杀毒软件具体命中了哪条规则。
- 源码中的远程数据端点为 Google OAuth 与 Google Drive；构建时还获取 Node 官方许可证。没有完成全部依赖和二进制供应链审计，因此不能把源码检查等同于确认最终 EXE 安全。

## 首次告警的处置及证据限制

- 首次构建异常改名为 .0xe 时，被错误地按失败构建处理；随后进行了重建和隔离功能测试。首次被改名的生成文件已被清理，没有保留其哈希。这是处置失误。
- 下表标识的是随后重建、目前留存的文件，**不能视为首次告警样本的哈希**。功能测试通过不代表恶意软件检测通过。
- 已停止重建和运行候选程序。源码及当前可加载插件目录的安装入口暂停；生成文件和已有 ZIP 留存，不删除用户资料，不修改杀毒软件设置，不加入排除项，不恢复并运行被拦截文件。

## 用户授权后的 0.4.1 整改与验证

用户随后明确要求同时修复新版应用且不添加危险代码，因此恢复了隔离候选版的源码修改、构建与验证；旧 SEA 文件没有重新运行。删除旧 SEA / postject 构建及相关依赖，移除脚本安装器、卸载脚本和运行时 Shell 调用。新版采用便携目录：原样复制具有 Valid / OpenJS Foundation 签名的 Node，附可读 .mjs 和 C# 源码；3 个原生 GUI 程序分别处理窗口、固定 stdio 通信及受限 Windows 操作。不包含任意命令执行接口、注入、安全软件设置修改或排除项操作。

仅用户主动操作时登记 HKCU 扩展主机、开启当前用户 Limited 小时任务；新增断开本机连接并关闭任务入口。DPAPI 使用当前用户密钥。候选版的完整清单和 SHA-256 位于 `dist/PKM-Nexus-Companion-0.4.1-candidate/candidate.json`。

已使用本机安装的 WithSecure `fsscan.exe` 对最终候选目录执行只读扫描（未启用删除、排除或恢复）：扫描 **7 项、有害 0 项**。扫描清单覆盖全部 4 个 EXE、管理页 HTML / JS 和共享模型 JS。默认策略并未扫描每份 .mjs，因此同时保留源码静态审查及禁止危险构建模式的检查。报告为 `test-results/security/companion-0.4.1-scan.txt`，逐文件扫描清单为 `companion-0.4.1-scanned.txt`。没有向外部提交样本。

118 项测试、真实 Chrome 通信 7 项、WinForms 托盘 / 无终端 / 退出清理、Windows 任务和 DPAPI 均通过。当前 3 个应用自编译 EXE 仍为 NotSigned，尚无可用发行签名证书。插件预览排除所有应用 ZIP，下载入口和发行构建继续关闭。原告警仍无厂商分析结论，新版扫描结果不能确认旧版是误报，也不能保证其他引擎或将来不报警。

## 用户要求完成修复并恢复新版下载

用户明确指出关闭下载不满足修复要求，要求保留小窗口、无终端、托盘和各用户自己的 Google Drive。0.4.1 使用不同于旧版的透明运行结构，执行新的检查后恢复内置下载，旧 0.4.0 仍禁止重新分发。

- 最终核心测试 119 项通过，真实 Chrome 通信 7 项及托盘测试通过；测试覆盖同一个应用客户端下两个用户的凭证和 Drive 归属隔离、换号保护。
- 从完整插件设置实际点击下载并保存 ZIP，SHA-256 与发行包一致；解压该下载文件，校验每个文件并运行真实 WinForms 界面，验证窗口、无终端、托盘、关闭恢复、单实例和退出清理。报告：`test-results/bundled-installer-report.json`。
- 当前应用目录扫描 7 项、有害 0 项；实际下载 ZIP 另扫 8 项、有害 0 项，清单包含 ZIP 内全部 4 个 EXE。报告：`test-results/security/companion-0.4.1-archive-scan.txt`。没有关闭杀毒软件、修改安全设置或添加排除项。
- 新构建要求官方 Node 的有效签名、当前构建后的无有害项目报告、全部 EXE 覆盖及文件清单一致。过期、缺失或有害报告不能打包。自编译应用的 NotSigned 状态如实写入 RELEASE.json，不再作为永久禁用下载的理由。尚不能承诺所有安全软件在所有电脑上的提示结果。
- Google OAuth 属于应用的一次性注册，每位用户独立登录。已在用户授权下创建独立 `pkm-nexus` 项目并启用 Drive API，后续授权仍由每位用户自己完成；不嵌入开发者或任何用户的访问、刷新令牌。
